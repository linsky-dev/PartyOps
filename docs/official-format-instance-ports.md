# 公文排版实例端口与启动诊断

主机和个人模式在各自 PartyOps 进程内启动回环排版服务。新配置写入 `PARTYOPS_OFFICIAL_FORMAT_PORT`；重配或覆盖升级保留已有有效值。旧个人配置在需要启动新进程时补齐该项，保留密钥、注释和业务数据路径。Linux 启动配置允许导入此项。

该值是首选端口。Windows 使用独占套接字，禁止将活跃地址复用到另一账号进程。首选端口被占用时由操作系统原子分配新端口，不连接占用者，不终止其他进程。实际端口记录在当前业务目录 `logs/official-format-endpoint.json`；下次启动先尝试该值，再重新独占绑定。记录必须匹配业务目录与配置首选值，它只用于续用端口，不能证明服务正在运行。用户显式更改首选值时旧记录失效；正常重启、升级可继续使用仍然空闲的已选端口。

本机票据接口只在当前应用对象持有就绪排版服务且密钥一致时签发，返回该对象实际端口。主页面 CSP 同步允许该端口；不能从陈旧配置或日志直接签发票据。服务未就绪返回 `LOCAL_FORMAT_NOT_READY`。协同电脑的助手接口继续使用电脑本地 `18768`，服务器动态端口不会下发为协同电脑地址。

独占绑定失败显示 `LOCAL_FORMAT_PORT_IN_USE`；数据目录或端点记录不可写显示 `LOCAL_FORMAT_CONFIG_WRITE_FAILED`。启动失败写入当前业务目录既有服务诊断协议，释放本次实例资源；不能跳过公文服务继续宣称完整启动成功。用户可复制向导中的诊断编号，业务数据不被删除。

安装版启动自检除主页面、数据库外，还检查本次子进程保存的排版记录：业务目录绑定、PID、随机启动实例标识、真实回环 `/health` 响应必须一致。该探针不发送票据或文档。组件自检仍不能替代真实 WPS、公文逐页金样和完整生命周期验收。

升级不会更改账号、数据库或附件结构。应用本修复后需要重建安装包，并在普通用户原始环境重新执行配置、启动、重启、覆盖升级以及真实排版验收；旧失败证据仍保留。回滚程序时先正常退出受影响实例；新端点记录只作为兼容性提示，旧程序不会依靠它获得通过结论。
