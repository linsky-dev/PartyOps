# 安全升级与故障恢复

适用于从已验证的 1.4.5-rc.6 环境迁移至 1.4.6-rc.1。使用合成库的演练回执另见[验收报告](ACCEPTANCE_REPORT.md)。

1. 安排停写窗口，核对源版本、目标包 SHA-256、兼容环境及可用磁盘。记录迁移前应用与数据库版本，保留原安装介质和受权限保护的本机 PKI、Fernet 与入网密钥。密钥单独备份。
2. 验证升级前归档的清单闭包、文件长度、SHA-256、SQLite 完整性及隔离恢复结果。关闭所有业务写入后执行受控安装。核对启动事务日志及目标模式 `0028`，再检查账号、会话、审计、附件、权限和主协同重连。
3. 应用尚未对外提供服务时，启动迁移失败可使用该次、已验证并绑定事务的升级前快照恢复。保留故障数据库和日志，核对原业务数据和附件后再恢复服务。
4. 应用提交升级并开始对外服务后，保留最新数据库、附件、审计、撤销记录和密钥版本。使用支持当前模式的修复版进程原位接管。原生更新器检测到账号恢复模式时阻断自动程序降级与旧快照恢复。
5. RC6 已打包的更新器缺少上述防护。在验证具备兼容保护的升级链前，使用人工停写和受控覆盖安装，在线更新目录暂不提供 RC6 至 RC1 的跨模式直升包。

生产发布后若仅官网回读失败，回滚至最近一次已核验的 EdgeOne 生产部署，并重新回读原清单及对外入口。软件业务数据库按上述事务阶段处理。
